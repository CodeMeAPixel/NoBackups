## Prerequisites

- A Linux server (amd64, arm64 or armv7) with root access, and any SSH client: PowerShell, Windows Terminal, PuTTY or macOS Terminal all work
- A bucket on any S3-compatible store, plus an access key and secret key. No bucket yet? Try the [local demo](#try-it-without-a-bucket) first.

## Back up a server

<Steps>
  <Step title="Install">
    SSH into the server, then clone and run the installer:

    ```bash
    git clone https://github.com/CodeMeAPixel/NoBackups
    cd NoBackups
    sudo sh install.sh
    ```

    It builds from source if Go is installed, otherwise it downloads the release binary for your server's CPU. See [Installation](/installation) for a no-clone one-liner and offline options.
  </Step>
  <Step title="Add your secrets">
    Credentials and passphrases go in `/etc/nobackups/nobackups.env` (`chmod 600`), not in the config file:

    ```bash /etc/nobackups/nobackups.env
    HETZNER_ACCESS_KEY=your-access-key
    HETZNER_SECRET_KEY=your-secret-key
    BACKUP_PASSPHRASE=a-long-random-passphrase
    ```

    <Warning>
      Store the passphrase somewhere other than the server too, like your password manager. A backup you can't decrypt is just very expensive random noise.
    </Warning>
  </Step>
  <Step title="Say what to back up and where">
    Edit `/etc/nobackups/config.yaml`. The installer created a fully commented example. A minimal version:

    ```yaml /etc/nobackups/config.yaml
    destinations:
      hetzner:
        type: s3
        endpoint: fsn1.your-objectstorage.com
        region: fsn1
        bucket: my-backups
        access_key_id: ${HETZNER_ACCESS_KEY}
        secret_access_key: ${HETZNER_SECRET_KEY}
        prefix: servers/{hostname}

    jobs:
      - name: system
        sources: [/etc, /root, /home]
        exclude: ["*.tmp", ".cache"]
        destinations: [hetzner]
        schedule: "15 3 * * *"
        one_file_system: true
        encryption:
          passphrase: ${BACKUP_PASSPHRASE}
        retention:
          keep_last: 7
          keep_days: 30
    ```
  </Step>
  <Step title="Check it">
    ```bash
    sudo nobackups validate   # is the config valid?
    sudo nobackups check      # can every destination be written to, listed and deleted from?
    ```

    ```text
    /etc/nobackups/config.yaml: OK (1 jobs, 1 destinations)
    ✓ hetzner              ok
    ```
  </Step>
  <Step title="Run the first backup">
    ```bash
    sudo nobackups run system
    sudo nobackups snapshots system
    ```
  </Step>
  <Step title="Turn on the schedule">
    ```bash
    sudo systemctl enable --now nobackups
    ```

    From now on the daemon runs every job on its `schedule`. Check on it with `nobackups status` or `journalctl -u nobackups`.
  </Step>
</Steps>

<Tip>
  Before you call it done, [restore a snapshot](/guides/restoring) into a scratch directory. Untested backups are just optimism with a cron schedule.
</Tip>

## Try it without a bucket

`make demo` runs a full encrypted backup and restore on local disk, with no credentials needed:

```bash
git clone https://github.com/CodeMeAPixel/NoBackups && cd NoBackups
make demo
```

(This one needs Go and make, so run it on Linux, macOS or WSL.)
