*Dump it like it's hot.*

NoBackups runs `pg_dump` / `pg_dumpall` for you. Both take a consistent snapshot without locking writers. See [Databases](/configuration/databases) for every option.

<Tabs>
  <Tab title="In Docker">
    Uses the tools inside the container, so nothing needs installing on the host:

    ```yaml
    - name: postgres
      databases:
        - type: postgres
          container: my-postgres
          user: postgres
          password: ${PG_PASSWORD}
      destinations: [offsite]
      schedule: "0 */6 * * *"
      retention: { keep_last: 28 }
    ```
  </Tab>
  <Tab title="On the host">
    Needs `postgresql-client`, ideally the same major version as the server:

    ```yaml
    - name: postgres
      databases:
        - type: postgres
          password: ${PG_PASSWORD}
      destinations: [offsite]
      schedule: "0 */6 * * *"
      retention: { keep_last: 28 }
    ```
  </Tab>
</Tabs>

Without `database`, every database plus roles and permissions is dumped with `pg_dumpall` (`postgres.sql`). To dump specific databases in the faster custom format, which can restore single tables, list them separately:

```yaml
- name: postgres-apps
  databases:
    - { type: postgres, container: my-postgres, password: "${PG_PASSWORD}", database: app }
    - { type: postgres, container: my-postgres, password: "${PG_PASSWORD}", database: analytics, options: ["--exclude-table-data=events_raw"] }
  destinations: [offsite]
  schedule: "0 */6 * * *"
```

## Restore

```bash
nobackups restore postgres --target /tmp/r --path nobackups-databases
```

```bash
pg_restore -U postgres -d app --clean --if-exists /tmp/r/nobackups-databases/postgres-app.dump   # one database
psql -U postgres -f /tmp/r/nobackups-databases/postgres.sql postgres                            # pg_dumpall
docker exec -i my-postgres pg_restore -U postgres -d app --clean --if-exists \
  < /tmp/r/nobackups-databases/postgres-app.dump                                                # into a container
```
