All you need is an SSH session to the server: PowerShell or Windows Terminal (`ssh` is built into Windows 10 and 11), PuTTY, macOS Terminal, or whatever you like.

## Clone and install (recommended)

```bash
git clone https://github.com/CodeMeAPixel/NoBackups
cd NoBackups
sudo sh install.sh
```

The installer picks the best way to get a binary:

- **Go 1.24+ on the server**: builds from the source you just cloned. See [Installing Go](#installing-go-optional) if you want this.
- **No Go**: downloads the matching release binary for the server's CPU (amd64, arm64 or armv7) and verifies its SHA-256 checksum. You don't need Go or make.

Then it installs the binary, config and systemd unit, as described in [What gets installed](#what-gets-installed).

<Tip>
  Already logged in as root? Drop the `sudo`: `sh install.sh`.
</Tip>

## Installing Go (optional)

You only need Go if you want the installer to **build from source**. Without it, the installer downloads a prebuilt release binary instead, which works just as well. Building from source is handy when you want to run a fix from a branch before it's released, or when you'd rather not run prebuilt binaries.

Check whether you already have a recent enough version:

```bash
go version   # needs go1.24 or newer
```

<Warning>
  Avoid `apt install golang` and other distro packages: they're often too old (Ubuntu 24.04 ships Go 1.22, for example). Use the official release from go.dev below.
</Warning>

<Steps>
  <Step title="Download and install the latest Go">
    Run as root on the server. This detects the CPU (amd64, arm64 or armv7), downloads the current release from [go.dev](https://go.dev/dl/), and installs it to `/usr/local/go`:

    ```bash
    GO_VERSION=$(curl -fsSL "https://go.dev/VERSION?m=text" | head -1)
    case $(uname -m) in
      x86_64)  GO_ARCH=amd64 ;;
      aarch64) GO_ARCH=arm64 ;;
      armv7l)  GO_ARCH=armv6l ;;
      *)       GO_ARCH=$(uname -m) ;;
    esac
    curl -fsSLO "https://go.dev/dl/${GO_VERSION}.linux-${GO_ARCH}.tar.gz"
    rm -rf /usr/local/go && tar -C /usr/local -xzf "${GO_VERSION}.linux-${GO_ARCH}.tar.gz"
    rm "${GO_VERSION}.linux-${GO_ARCH}.tar.gz"
    echo 'export PATH=$PATH:/usr/local/go/bin' > /etc/profile.d/go.sh
    . /etc/profile.d/go.sh
    go version
    ```

    You should see something like `go version go1.25.1 linux/amd64`.
  </Step>
  <Step title="Open a new SSH session">
    `/etc/profile.d/go.sh` adds Go to your `PATH` for every future login. If `go` reports `command not found` in another shell, log out and back in.

    You don't need to configure anything for `sudo`: `install.sh` looks in `/usr/local/go/bin` itself, even when `sudo` resets your `PATH`.
  </Step>
  <Step title="Install NoBackups from source">
    ```bash
    cd NoBackups
    sudo sh install.sh
    ```

    Look for `==> building … from source with go1.25.1` in the output.
  </Step>
</Steps>

### Trying an unreleased fix

With Go installed, you can run any branch before it's released:

```bash
cd NoBackups
git fetch origin
git checkout <branch-name>
sudo sh install.sh
```

Switch back with `git checkout master && git pull && sudo sh install.sh`.

### Upgrading or removing Go

Re-run the commands above to upgrade; they replace `/usr/local/go` with the latest release. To remove Go entirely:

```bash
rm -rf /usr/local/go /etc/profile.d/go.sh
```

NoBackups keeps working after Go is removed, because the installed binary has no dependencies. Future `install.sh` runs will download release binaries instead of building.

## Other ways to install

<Tabs>
  <Tab title="One-liner, no clone">
    Downloads and verifies the latest release binary; nothing else is left on the server.

    ```bash
    curl -fsSL https://raw.githubusercontent.com/CodeMeAPixel/NoBackups/master/install.sh | sudo sh
    ```

    No `curl`? `wget -qO- <same URL> | sudo sh` works too.
  </Tab>
  <Tab title="Upload a binary">
    For servers without internet access, or if you'd rather not pipe scripts into a shell:

    1. Download `nobackups-linux-amd64` (or `-arm64` / `-armv7`) from the [GitHub releases page](https://github.com/CodeMeAPixel/NoBackups/releases).
    2. Copy it to the server, using WinSCP or FileZilla on Windows, or `scp` from any terminal (also built into Windows 10 and 11):

       ```powershell
       scp .\nobackups-linux-amd64 root@your-server:/tmp/
       ```

    3. On the server:

       ```bash
       chmod +x /tmp/nobackups-linux-amd64
       sudo /tmp/nobackups-linux-amd64 install
       ```

    The binary installs itself: the systemd unit and config templates are built in.
  </Tab>
  <Tab title="make deploy (macOS / Linux / WSL)">
    If your own machine has Go, make and ssh, you can build locally and push to a server in one go:

    ```bash
    make deploy HOST=root@web01
    make deploy HOST=admin@pi ARCH=armv7     # ARCH: amd64 (default), arm64, armv7
    make deploy HOST=root@box SUDO=          # logging in as root on a host without sudo
    ```
  </Tab>
</Tabs>

## Installer options

Put them **after** `sudo`, because `sudo` drops variables set before it: `sudo NOBACKUPS_VERSION=v0.2.0 sh install.sh`, or with the one-liner `curl ... | sudo NOBACKUPS_VERSION=v0.2.0 sh`.

| Variable | Effect |
|---|---|
| `NOBACKUPS_VERSION=v0.2.0` | Install a specific release instead of the latest |
| `NOBACKUPS_SOURCE=release` | Always download the release binary, even in a clone with Go |
| `NOBACKUPS_SOURCE=build` | Always build from source; fail if Go isn't available |
| `NOBACKUPS_DOWNLOAD_URL=https://mirror.example/nobackups` | Download release files from a mirror (it must serve the binaries and `SHA256SUMS`) |

You can also install a binary you already have: `sudo sh install.sh ./nobackups-linux-amd64`.

## What gets installed

| Path | What |
|---|---|
| `/usr/local/bin/nobackups` | The binary (static, no dependencies) |
| `/etc/nobackups/config.yaml` | Your config, created from the built-in example if missing |
| `/etc/nobackups/nobackups.env` | Secrets, `chmod 600`, created if missing |
| `/etc/systemd/system/nobackups.service` | The systemd unit |
| `/var/lib/nobackups` | Locks and last-run status (created on first run) |

Existing config and env files are never overwritten. If the service is already running, it's restarted on the new version.

## After installing

```bash
sudo nano /etc/nobackups/config.yaml /etc/nobackups/nobackups.env
sudo nobackups validate && sudo nobackups check
sudo nobackups run --all
sudo systemctl enable --now nobackups
```

## Upgrading

Run the same thing again:

```bash
cd NoBackups && git pull && sudo sh install.sh     # clone
curl -fsSL https://raw.githubusercontent.com/CodeMeAPixel/NoBackups/master/install.sh | sudo sh   # one-liner
```

Your config is kept and the running service is restarted on the new version.

## Packaging

`nobackups install` takes flags for custom layouts. `--root` installs into a staging directory and skips `systemctl`:

```bash
nobackups install --root ./pkgroot --bin-dir /usr/bin --unit-dir /usr/lib/systemd/system
make install PREFIX=/usr DESTDIR=./pkgroot    # same thing via make
```

## Uninstalling

```bash
sudo nobackups uninstall
```

This stops and disables the service, and removes the binary and unit. Your config, state and (obviously) your backups stay put. We're not monsters.
