title: "Destinations"
description: "Where your data goes on holiday. Any S3-compatible store, or a local directory."

---

Destinations are named once, then referenced from jobs by name:

```yaml
destinations:
  hetzner:            # ← the name jobs use
    type: s3
    ...
  nas:
    type: local
    path: /mnt/nas/backups

jobs:
  - name: system
    destinations: [hetzner, nas]
```

Names may contain letters, digits, `.`, `_` and `-`.

## Common options

<ParamField path="type" type="string" required>
  `local` for a directory, `s3` for any S3-compatible object store, or a [provider shorthand](#providers) such as `alarik` or `hetzner` that fills in that provider's defaults.
</ParamField>

<ParamField path="prefix" type="string">
  Key prefix (S3) or subdirectory (local) under which job folders are created. `{hostname}` is replaced with the server's hostname, so a single bucket can serve a whole fleet:

  ```yaml
  prefix: servers/{hostname}     # → servers/web01/<job>/...
  ```

  If the value **starts** with `{`, quote it, or YAML reads it as a map:

  ```yaml
  prefix: "{hostname}"
  ```
</ParamField>

## S3 options

<ParamField path="endpoint" type="string">
  Host, with an optional port, e.g. `cdn.example.com` or `10.0.0.5:9000`. Required unless the provider derives it from `region`. Prefix with `http://` to use plain HTTP; `https://` is the default.
</ParamField>

<ParamField path="bucket" type="string" required>
  The bucket must already exist. `nobackups check` tells you if it doesn't.
</ParamField>

<ParamField path="access_key_id" type="string" required />
<ParamField path="secret_access_key" type="string" required />

<ParamField path="session_token" type="string">
  For temporary credentials.
</ParamField>

<ParamField path="region" type="string" default="us-east-1">
  Most self-hosted stores ignore this.
</ParamField>

<ParamField path="path_style" type="boolean" default="depends on the provider">
  Use `https://endpoint/bucket/key` addressing instead of `https://bucket.endpoint/key`. Most self-hosted stores need `true`, which is the default for the `alarik`, `rustfs`, `minio` and `garage` types. With plain `type: s3`, NoBackups picks automatically.
</ParamField>

<ParamField path="use_ssl" type="boolean" default="true">
  Normally inferred from the endpoint's `http://` or `https://` prefix.
</ParamField>

<ParamField path="storage_class" type="string">
  E.g. `STANDARD_IA` or `GLACIER_IR` on AWS.
</ParamField>

<ParamField path="part_size_mb" type="integer" default="64">
  Multipart upload chunk size, minimum 5. The largest possible snapshot is 10,000 × this (640 GB at the default). Memory use is roughly this much per destination. Raise it for very large backups.
</ParamField>

<ParamField path="ca_file" type="string">
  PEM file with a private CA certificate, for self-hosted stores behind an internal CA.
</ParamField>

<ParamField path="insecure_skip_verify" type="boolean" default="false">
  Skip TLS certificate verification. Last resort for self-signed certificates; prefer `ca_file`.
</ParamField>

## Local options

<ParamField path="path" type="string" required>
  Absolute path to a directory, e.g. a second disk or an NFS mount. Snapshots are written to a `.partial` file first, then renamed, so a half-written file never looks like a snapshot.
</ParamField>

## Providers

Instead of `type: s3`, you can name the provider. It's still S3 underneath, but NoBackups fills in that provider's defaults, and `nobackups list` shows which provider each destination uses. Anything you set yourself (`endpoint`, `region`, `path_style`) overrides the defaults.

| `type` | Defaults |
|---|---|
| `alarik`, `rustfs`, `minio` | `path_style: true`. Set `endpoint` to your server. |
| `garage` | `path_style: true`, `region: garage` |
| `hetzner` | Endpoint from `region` (`fsn1`, `nbg1`, `hel1`) → `fsn1.your-objectstorage.com` |
| `aws` | Endpoint from `region` → `s3.eu-central-1.amazonaws.com`. Region defaults to `us-east-1`. |
| `b2` | Endpoint from `region` → `s3.eu-central-003.backblazeb2.com` |
| `digitalocean` | Endpoint from `region` → `ams3.digitaloceanspaces.com` |
| `wasabi` | Endpoint from `region` → `s3.eu-central-1.wasabisys.com` |
| `r2` | `region: auto`. Set `endpoint` to `<account-id>.r2.cloudflarestorage.com`. |
| `s3` | Nothing filled in: set `endpoint` for any other S3-compatible service |

<Tabs>
  <Tab title="Alarik">
    [Alarik](https://github.com/achtungsoftware/alarik) is a self-hosted, S3-compatible store.

    ```yaml
    alarik:
      type: alarik
      endpoint: s3.example.com      # or http://10.0.0.5:8080 for plain HTTP
      bucket: backups
      access_key_id: ${ALARIK_ACCESS_KEY}
      secret_access_key: ${ALARIK_SECRET_KEY}
      prefix: "{hostname}"
    ```

    If the endpoint is behind Cloudflare, see [Troubleshooting](#troubleshooting).
  </Tab>
  <Tab title="Hetzner">
    Create credentials under **Object Storage → Security credentials** in the Hetzner Console.

    ```yaml
    hetzner:
      type: hetzner
      region: fsn1                  # fsn1, nbg1 or hel1
      bucket: my-backups
      access_key_id: ${HETZNER_ACCESS_KEY}
      secret_access_key: ${HETZNER_SECRET_KEY}
      prefix: servers/{hostname}
    ```
  </Tab>
  <Tab title="RustFS / MinIO / Garage">
    ```yaml
    rustfs:
      type: rustfs                  # or minio / garage
      endpoint: http://rustfs.internal:9000
      bucket: backups
      access_key_id: ${RUSTFS_ACCESS_KEY}
      secret_access_key: ${RUSTFS_SECRET_KEY}
      prefix: "{hostname}"
    ```
  </Tab>
  <Tab title="AWS S3">
    ```yaml
    aws:
      type: aws
      region: eu-central-1
      bucket: my-backups
      access_key_id: ${AWS_ACCESS_KEY_ID}
      secret_access_key: ${AWS_SECRET_ACCESS_KEY}
      storage_class: STANDARD_IA
    ```
  </Tab>
  <Tab title="Cloudflare R2">
    ```yaml
    r2:
      type: r2
      endpoint: <account-id>.r2.cloudflarestorage.com
      bucket: my-backups
      access_key_id: ${R2_ACCESS_KEY}
      secret_access_key: ${R2_SECRET_KEY}
    ```
  </Tab>
  <Tab title="Backblaze B2">
    ```yaml
    b2:
      type: b2
      region: eu-central-003
      bucket: my-backups
      access_key_id: ${B2_KEY_ID}
      secret_access_key: ${B2_APP_KEY}
    ```
  </Tab>
  <Tab title="Other S3">
    ```yaml
    other:
      type: s3
      endpoint: s3.example.net
      region: us-east-1
      bucket: my-backups
      access_key_id: ${S3_ACCESS_KEY}
      secret_access_key: ${S3_SECRET_KEY}
    ```
  </Tab>
  <Tab title="Local / NFS">
    ```yaml
    nas:
      type: local
      path: /mnt/nas/backups
      prefix: "{hostname}"
    ```
  </Tab>
</Tabs>

<Tip>
  Give backup credentials the least privilege you can: read, write, list and delete on **one** bucket (or prefix). Bucket versioning or object lock protects you if a server is compromised and someone tries to delete its backups.
</Tip>

## Testing destinations

```bash
nobackups check
```

For each destination, this checks the bucket exists (S3), then writes, lists and deletes a small test object:

```text
✓ hetzner              ok
✗ rustfs               write: The Access Key Id you provided does not exist in our records.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="ETag mismatch for part 1" icon="triangle-exclamation">
    Usually means a CDN or reverse proxy sits between NoBackups and the storage server and rewrites the `ETag` header. Cloudflare's orange-cloud proxy is the usual suspect: it can turn `"abc"` into the weak form `W/"abc"`, which some servers (e.g. Alarik) then fail to match.

    NoBackups handles weakened ETags, so updating fixes the error. You're still better off pointing `endpoint` at a hostname that **isn't** proxied, such as a DNS-only (grey-cloud) record or the server's own address. Proxying backups through a CDN adds latency, and Cloudflare limits request bodies to 100 MB on most plans, so keep `part_size_mb` below that if you must proxy.
  </Accordion>
  <Accordion title="See exactly what the server returns" icon="magnifying-glass">
    Set `NOBACKUPS_S3_TRACE=1` to print every S3 request and response header (signatures are redacted):

    ```bash
    sudo NOBACKUPS_S3_TRACE=1 nobackups check
    ```
  </Accordion>
</AccordionGroup>
